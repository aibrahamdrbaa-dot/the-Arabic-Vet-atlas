# Living Anatomy — UI/UX redesign brief (2026-11-26)
Status: proposed implementation direction, not a shipped UI. Owner rejected the engineering prototype aesthetic (0/10). Keep the validated P0 core and redesign the product shell. Reference: user-supplied 57.7s Little Oink tutorial, inspected at 22 timestamps by Roy. It shows a dominant pink pig on vivid blue, small editorial elements, generated consistent image variants, layout composition and a coding handoff. Use its creative method and hierarchy, not its brand, pig, exact layout, text or assets. The video itself is not redistributed.
## Product direction
Arabic-first living digital anatomy museum: welcoming editorial landing, then calm precision study workspace. Use a CAT (not pig) as the home visual character; canine remains first planned scientific dataset, feline a separate planned route, unless owner changes scientific priority. Cat imagery is illustrative, never anatomical evidence. No false availability counts or fabricated structures. Species availability computed from actual reviewed catalog.
## Navigation and pages
Home /#/ -> species /#/animals -> /#/animals/dog or cat -> systems /#/animals/dog/skeletal -> specimens /#/specimens/:id -> structure selection /#/specimens/:id?structure=:id (stable IDs, one-to-many mapping). Use a small tested hash router or equivalent static-host-safe navigation, with back/forward and deep links. No new heavy framework. Search /#/search (Arabic/English/Latin, normalization for search only, no rewriting canonical terminology). About /#/about (method, sources, licenses and contributors). Study notes / quizzes only when implemented; indicate planned states. Species pages group systems and regions (head, axial skeleton, thoracic limb, pelvic limb etc), not hardcoded fake content. Each path must be functional even with empty catalog and provide next actions.
## Visual design
Proposed palette: warm ivory #F7F4EC, cobalt #235CE3, ink #172334, peach #ECA878, white. Recheck contrast; peach accents not body text. Arabic-first expressive large headline with readable Arabic type (candidate IBM Plex Sans Arabic or Noto Sans Arabic; check license, self-host only if permitted; system fallback); compact body; Latin labels LTR bdi. Editorial asymmetry, generous whitespace, limited borders, no generic equal-card dashboard or purple gradient template. Build design tokens and consistent type scale, spacing, radius, focus and states. Home: small brand/navigation, large cat cutout dominant, Arabic headline "اكتشف التشريح من الداخل", primary CTA "استكشف الأطلس", optional secondary "كيف يعمل؟"; next section choose species with cat/dog cards and transparent planned labels, then explore systems, how to study, trust/source section. Avoid fake counters and placeholder lorem. The anatomy workspace is calmer: large canvas, logical direction controls, mobile bottom sheet or inline details, search/filter, anatomy title ar/en/la, source and review status, selection/isolation/reset, accessible non-WebGL textual fallback. Preserve working Viewer and scientific gates; no artificial generated anatomy.
## Generated art pipeline (Neon)
Use available Nano Banana image generation (owner mentioned Nano Banana 2.1; verify actual model/access), only original exterior animal editorial images. Build character reference sheet for same adult domestic shorthair orange tabby with white chest, stable markings, proportions, eyes, pose, camera and soft daylight. Generate one hero full-body seated cutout on transparent or clean solid backdrop, three consistent poses/gaze variants (front, 3/4, side), and matching canine exterior for species card. Keep main focal area adaptable to portrait and desktop; no text/labels in images, no human/pig, no anatomical cutaway, no false medical representation. Generate 3 candidates for hero, select on visual QA, maintain reference IDs/prompt/model/date/license/use log. Do not publish images unless permitted by service terms; distinguish generated editorial assets from scientific models. Store only optimized derivatives under public/images/editorial/ with metadata outside public/models. Use AVIF/WebP, srcset, width/height, hero priority; avoid autoplay video and huge image sequences. Hero budget target <=250KB mobile, <=500KB desktop, other images lazy. Never use generated anatomy even as scientific thumbnails; use real approved model renders or abstract non-anatomical icons.
## Interaction
CSS transitions for navigation, focus/press feedback, purposeful shared-element transitions with optional View Transition API feature detection, motion library only if measurable need. Suggested 150–250ms for UI and 300–500ms for major entrance. Cat layered pose crossfade on tap/hover if it adds orientation; no pointer-only affordance; no forced scroll, no endless parallax, no blocking loader. Reduced motion removes spatial animation. No WebGL on landing; lazy load viewer only in specimen route. Avoid persistent render loops and preserveDrawingBuffer in production unless measured need. No new backend or paid services.
## Acceptance and delivery

Test mobile 360/390, tablet 768, desktop 1440; navigation/back/deep link/keyboard, reduced motion, contrast WCAG AA, 44px targets, no overflow and no dead ends. Keep both mandatory CI jobs green; update smoke assertions deliberately if production landing changed, never remove Viewer E2E. Add page screenshots and walkthrough video (optional) as artifact; inspect visually before claiming. Check initial transfer budgets (<500KB mobile hero+initial app as aspiration, measure and report), no Three.js requests on home, Lighthouse metrics measured under documented simulated settings, actual phone later. No public deploy required; use GitHub artifacts or Codespaces preview. No fake verified assets. UI can proceed alongside P1 data pilot on separate branches; avoid conflicts around App.tsx and catalog.
